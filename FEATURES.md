# Что умеет SkyrimTools

С этим набором Claude Code становится помощником модера, который видит твою сборку изнутри. Он читает
плагины прямо из папки MO2, пишет патчи, знает синтаксис популярных фреймворков и умеет разбирать краши.
Просить можно обычными словами, по-русски. Ниже — что именно он умеет и примеры запросов.

Набор не привязан к Claude Code: те же скиллы и серверы работают с Codex, VS Code с Copilot, Cursor, Windsurf,
Cline, Gemini CLI — см. [AGENTS.md](AGENTS.md) и [INSTALL.md](INSTALL.md#другие-агенты-не-claude-code).

Установка: [INSTALL.md](INSTALL.md).

## 1. Разобраться в своей сборке (houseCARL)

houseCARL читает профиль MO2 так же, как его видит игра: порядок модов, `plugins.txt`, все записи всех плагинов.
MO2 при этом запускать не нужно.

- **Кто победил в записи** и кто её перезаписывает: полное дерево конфликтов по любой записи или по целому плагину.
- **Сравнение плагинов**: что именно мод A меняет относительно мода B или ванили, поле за полем.
- **Массовые запросы**: «все мечи с уроном от 20», «все NPC с фракцией X», «все записи, которые трогает Requiem.esp».
- **Неактивные плагины**: что будет, если включить плагин, который сейчас выключен.
- **Файлы и ассеты**: какой мод выигрывает в конкретной текстуре или меше, что лежит в BSA.
- **Слой SKSE**: какие DLL-плагины стоят и чем настроены их ini/json. Слой SkyPatcher: что делают его INI после применения.
- **Nexus без браузера и без API-ключа**: поиск модов, файлы, требования, changelog, проверка обновлений твоей
  сборки, опознание непонятного архива по MD5.

> «Почему у железного меча такой урон? Кто его меняет?»
> «Какие моды конфликтуют с Immersive Armors и кто побеждает?»
> «Проверь, есть ли обновления для модов в сборке.»

## 2. Чинить и патчить

Всё, что пишет houseCARL, попадает в **новый плагин в новой папке мода**. Твои плагины остаются как были, а
изменения начинают действовать, только когда ты сам включишь этот мод в MO2. Правка существующего плагина «на месте»
возможна, но только по прямой просьбе.

- **Патч совместимости**: перенести нужные поля из нескольких модов в одну запись (forward), откатить запись к ванили.
- **Правка любых полей**: урон, вес, цена, статы, ключевые слова, условия, содержимое сундуков, левел-листы.
- **Новые записи и плагины**: создать предмет, заклинание, перк, NPC, диалог (с проверкой).
- **Ремонт**: битые ссылки на несуществующие записи, отсутствующие мастера, тёмные лица NPC (facegen).
- **ESL**: сжать FormID плагина под ESL (compact), объединить несколько плагинов в один (merge).
- **Внешность NPC**: перенести внешность из одного мода в другой.
- **NIF**: посмотреть и поправить внутренности меша.
- **BSA**: распаковать, посмотреть содержимое, перепаковать.
- **Papyrus**: декомпилировать чужой `.pex`, скомпилировать свой скрипт.

> «Сделай патч, чтобы броня из мода X попадала в левел-листы бандитов.»
> «В логе ругается на missing master — найди и почини.»
> «Сделай этот плагин ESL-флагнутым, если можно.»

## 3. Моды без ESP: SPID, KID, SkyPatcher, OAR

Для каждого фреймворка есть скилл с точной грамматикой нужной версии. Ошибка в одном токене у них обычно
молча ничего не делает, а скилл не даёт её допустить и объясняет, почему строка не срабатывает.

| Что нужно | Чем | Пример |
|---|---|---|
| Раздать NPC заклинания, перки, предметы, аутфиты, фракции по группам | **SPID** 7.3 (`_DISTR.ini`) | «дай всем магам-некромантам перк X с 30 уровня» |
| Повесить ключевые слова на предметы | **KID** 3.5 (`_KID.ini`) | «пометь все кинжалы из мода X ключевым словом WeapTypeDagger» |
| Изменить поля записей без плагина, положить предметы в сундук | **SkyPatcher** 6.4 | «снизь вес всех тяжёлых доспехов на 20%» |
| Подменить анимации по условиям (оружие, раса, перк) | **OAR** 3.0 | «включай эти атаки только с двуручным топором»; перевести DAR-условия в OAR |

Черновик SkyPatcher houseCARL может проверить офлайн, против твоей сборки.

## 4. Справочники под рукой

- **Papyrus**: точные сигнатуры функций, событий и свойств ванили, SKSE и популярных библиотек (PapyrusUtil,
  JContainers, MCMHelper, po3, SkyUI и ещё десятки). Claude не будет выдумывать функцию, которой нет.
- **Схемы записей**: все поля 133 типов записей (ARMO, WEAP, NPC_, MGEF…), их типы и допустимые значения перечислений.

> «Какой функцией SKSE узнать, что у актора надето в слот 32?»
> «Какие поля есть у MGEF и что значит флаг X?»

**Компиляция Papyrus** (`scripts\papyrus\papyrusc.py`, скилл `papyrus-compiler`): `.psc` -> `.pex` без Creation Kit —
компилятором с открытым кодом, который ставит `setup.cmd`, или родным `PapyrusCompiler.exe`, если CK есть. Импорты
собираются из твоего MO2 в порядке приоритета модов (SKSE, SkyUI, PapyrusUtil — откуда они реально берутся), а
недостающие ванильные исходники заменяются заголовками, сделанными из `.pex` самой игры. Готовый `.pex` кладётся в
новую папку мода, в чужой мод скрипт писать не даст.

> «Добавь в этот скрипт уведомление и скомпилируй.»
> «Почему не компилируется: unknown type SKI_ConfigBase?»

## 5. Свои SKSE-плагины на C++

Скилл по CommonLibSSE-NG: скелет плагина, регистрация нативных функций Papyrus, подписка на события, хуки через
trampoline и Address Library, одна DLL для SE + AE + VR. Отдельно разобраны ошибки, которые компилируются чисто,
но ломаются при загрузке игры.

> «Напиши SKSE-плагин, который логирует каждый удар по игроку.»

## 6. Краши, зависания и реверс (SE 1.5.97, ставится с `-Ghidra`)

- **Разбор crash log**: адреса `SkyrimSE.exe+XXXX` переводятся в ID Address Library и имена функций. Адреса
  в чужих DLL — по их `.pdb`.
- **Зависшая игра**: снимок всех потоков работающего процесса. Видно, какой поток крутится и на чём ждёт главный.
- **Ghidra через Claude**: декомпиляция и дизассемблирование SkyrimSE.exe и чужих SKSE-DLL, поиск ссылок, строк,
  слотов vtable. Найденные функции можно переименовать, и в следующий раз проект откроется уже с этими именами.
- **Проверка перед хуком**: адрес, ID или «IDA говорит» из чужого комментария сверяется с реальным кодом.

> «Вот crash log — что упало и какой мод виноват?»
> «Игра висит прямо сейчас — посмотри, что происходит.»

## 7. Мелкие утилиты

- `espscan.py` — сырые записи плагина без houseCARL. `pexdis.py` — дизассемблер `.pex`.
- `merge_ini.py` — добавить новые ключи из обновлённого ini мода, не затерев твои настройки.
- `font_has.py` — есть ли в шрифте нужные символы (например, кириллица для SkyUI / FLICK).

## 8. Правила работы

Скилл `skyrim-modding-practices` задаёт привычки, выученные на практике:
- не перезаписывать ini, которые ты подкрутил в игре: новые ключи добавляются, твои значения остаются;
- не писать в папки чужих модов: только новый мод (патч, INI для SPID/KID/SkyPatcher, сабмод OAR);
- не трогать `ModOrganizer.ini`, пока MO2 запущен (MO2 перезапишет его при выходе);
- коммитить каждое законченное изменение, чтобы его было легко откатить;
- честно говорить, что проверено, а что нет. В игре проверяешь только ты, и Claude так и пишет: «собрано, в игре не проверено».

## Чего он не делает

- Не запускает игру и не видит, что происходит на экране: проверка в игре всегда за тобой.
- Не включает моды в MO2 сам: новый патч появляется отдельной папкой мода, а включаешь его ты.
- Не пересоздаёт за генераторы их вывод (DynDOLOD, Synthesis, ParallaxGen) — их нужно перезапустить.
- RE-часть рассчитана на Skyrim SE 1.5.97. На AE (1.6.x) работает всё, кроме неё.
